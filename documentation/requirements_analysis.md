# Анализ требований: Трекер тренировок CrossFit

**Версия:** 2.0 (Обновлено на основе деталей из KIRO и обсуждения)

## 1. Техническое видение
*   **Платформа:** **Progressive Web App (PWA)**. Это веб-сайт, который можно "установить" на телефон как приложение (иконка на рабочем столе, работа без интерфейса браузера).
*   **Стек:**
    *   **Frontend:** Next.js + Tailwind CSS (для PWA и современного UI).
    *   **Backend:** Реальный бэкенд на Node.js (или в рамках Next.js) + База данных PostgreSQL.
    *   **Развертывание:** Локальная разработка (Docker), с возможностью переноса на VPS (Timeweb).
*   **Дизайн:** Агрессивный, энергичный стиль (CrossFit aesthetics), темная тема, крупные шрифты.

## 2. Бизнес-логика и Роли

### Модель подписки
*   **Клубная подписка (20 000 руб/мес):** Владелец платит за клуб. Все посетители, привязанные к клубу, пользуются приложением бесплатно в рамках этого клуба.
*   **Личная подписка (399 руб/мес):** Пользователь платит сам за себя, если он тренируется самостоятельно или его клуб не использует приложение.
*   *Примечание:* На старте — ручная активация подписок (без платежного шлюза).

### Роли
1.  **Администратор:** Глобальное управление.
2.  **Владелец клуба:** Создает клуб, управляет подпиской, видит статистику клуба.
3.  **Посетитель:** Тренируется, ведет дневник, участвует в рейтингах.

### Сценарии записи результатов
1.  **Самостоятельная запись:** Участник сам заходит в приложение и вносит свои результаты.
2.  **Запись тренером (Proxy Logging):** Владелец клуба/Тренер может выбрать участника из списка и внести результат за него.

### Типы тренировок по авторству
1.  **Клубная тренировка (WOD):** Создает Владелец. Видна всем участникам клуба в календаре на этот день.
2.  **Личная тренировка:** Создает сам Атлет (вне зависимости от членства в клубе). Видна только ему (и тренеру).

## 3. Структура тренировки (Domain Model)

Каждая **Тренировка (Session)** может состоять из двух частей (блоков):

### Блок 1: Skill (Сила / Навык)
*   **Цель:** Отработка техники или силовой рекорд.
*   **Структура:** Упражнение + Схема (Подходы x Повторения).
*   **Учет:** Максимальный взятый вес в рамках схемы.
*   *Пример:* Присед 5 подходов (10-10-8-8-6).
*   **История:** Сохранение "Личных рекордов" (PR) по каждому упражнению с датой.

### Блок 2: WOD (Workout of the Day)
*   **Типы:**
    *   **EMOM:** Ежеминутно.
    *   **AMRAP:** Максимум раундов/повторений за время.
    *   **For Time:** Сделать объем работы за минимальное время.
    *   **For Load:** Найти макс. вес.
    *   **Tabata, Chipper, Ladder.**
*   **Инструментарий:**
    *   *Cardio:* Bike, Row, Ski, Run.
    *   *Weights:* Barbell, Dumbbell, Kettlebell.
    *   *Gymnastics/Bodyweight:* Pull-ups (Chest-to-bar, Strict), Push-ups (Hand-release), Burpee, Devil Press, Wall Walks, и т.д.
*   **Результат:** Зависит от типа (Время, Кол-во, Вес).

## 4. Логика Лидербордов и Рейтинга

Это самая сложная часть. Нужно справедливо сравнивать атлетов.

### Типы лидербордов
1.  **Клубный:** Соревнуются только члены одного клуба.
2.  **Общий (Глобальный):** Все пользователи приложения.

### Фильтры
*   Период: День, Неделя, Месяц, Год, Все время.
*   Категория: Общий, Мужчины, Женщины.

### Система очков (Scoring Logic)
*Проблема:* Как сравнить атлета, сделавшего WOD с 40кг за 5 мин, и атлета с 50кг за 6 мин?
*   **Rx (Как предписано):** Выполнение WOD без изменений. Всегда выше Scaled.
*   **Scaled (Масштабируемый):** Облегченный вариант.
    *   *Гипотеза формулы:* `Базовые очки за место` + `Бонус за вес` - `Штраф за время` (требует моделирования).

## 5. Профиль и Геймификация
*   **Профиль:** Фото, Био, Контакты, Эмблема клуба.
*   **Приватность:** "Только я", "Только клуб", "Все".
*   **Вовлечение:**
    *   Стрики (дни подряд).
    *   Бейджи (ачивки).
    *   Уведомления ("Вася побил твой рекорд!").

## 6. База упражнений
*   Предустановленная база (популярные движения).
*   Возможность добавления пользовательских упражнений (с проверкой на дубли/опечатки — *нужен нечеткий поиск*).
