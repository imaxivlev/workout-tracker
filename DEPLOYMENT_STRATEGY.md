# Стратегия деплоя: Staging → Production

## Обзор

Проект использует двухэтапную стратегию деплоя для безопасного тестирования перед выкаткой на production.

## Окружения

### Staging (Тестовое)
- **Назначение:** Тестирование новых фич перед production
- **URL:** `staging.yourdomain.com` или `workout-tracker-staging.timeweb.cloud`
- **БД:** `workout_tracker_staging`
- **Данные:** Тестовые данные, можно удалять/пересоздавать
- **Email:** Тестовые письма (можно использовать свой email)

### Production (Боевое)
- **Назначение:** Реальные пользователи
- **URL:** `app.yourdomain.com` или основной домен
- **БД:** `workout_tracker_production`
- **Данные:** Реальные данные пользователей (бэкапы обязательны!)
- **Email:** Реальные письма пользователям

## Workflow разработки

```
Локальная разработка (опционально)
         ↓
    Git Push
         ↓
Staging на Timeweb (автоматический деплой)
         ↓
  Тестирование
         ↓
    Все ОК?
         ↓
Production на Timeweb (ручной деплой)
```

## Что нужно на Timeweb

### Для Staging:
1. MySQL БД: `workout_tracker_staging`
2. Node.js хостинг: `staging.yourdomain.com`
3. SMTP credentials (общие для staging и production)
4. Переменные окружения с staging DATABASE_URL

### Для Production:
1. MySQL БД: `workout_tracker_production`
2. Node.js хостинг: `app.yourdomain.com`
3. Те же SMTP credentials
4. Переменные окружения с production DATABASE_URL

## Преимущества подхода

✅ **Безопасность:** Тестируешь на staging, не ломаешь production
✅ **Уверенность:** Видишь, как работает на реальном сервере
✅ **Откат:** Если что-то сломалось на staging, production не затронут
✅ **Экономия:** Можно использовать один тариф Timeweb для обоих окружений

## Минусы локальной разработки (почему staging лучше)

❌ Нужно устанавливать MySQL/Docker локально
❌ Разные окружения (Windows vs Linux на сервере)
❌ Могут быть проблемы с портами, правами доступа
❌ Нужно синхронизировать версии Node.js, MySQL

## Рекомендуемый тариф Timeweb

**Тариф "Optimal"** (~400-500 руб/мес):
- 2 Node.js приложения (staging + production) ✓
- 2 MySQL БД ✓
- 2 GB RAM ✓
- SMTP включен ✓
- SSL для обоих доменов ✓

Или можно начать с **"Start"** (~200-300 руб/мес) и использовать одну БД для staging, а production добавить позже.

## Процесс деплоя

### Первый раз (Staging):
1. Создать MySQL БД на Timeweb
2. Создать Node.js хостинг
3. Подключить GitHub репозиторий
4. Настроить переменные окружения
5. Деплой произойдет автоматически
6. Выполнить миграции через SSH или панель управления
7. Протестировать все функции

### Выкатка на Production:
1. Убедиться, что staging работает идеально
2. Создать production БД
3. Создать production хостинг
4. Настроить переменные окружения с production DATABASE_URL
5. Выполнить миграции
6. Открыть для пользователей

## Тестирование на Staging

Что проверить перед выкаткой на production:
- [ ] Регистрация и вход работают
- [ ] Email верификация приходит
- [ ] Создание/редактирование/удаление тренировок
- [ ] Статистика считается правильно
- [ ] PWA устанавливается на телефон
- [ ] Оффлайн режим работает
- [ ] Миграция из localStorage работает
- [ ] Нет ошибок в логах
- [ ] Все тесты проходят

## Итого

Staging на Timeweb - это оптимальный вариант для твоего проекта:
- Не нужно настраивать локально
- Тестируешь на реальном окружении
- Безопасно для production
- Просто и быстро
