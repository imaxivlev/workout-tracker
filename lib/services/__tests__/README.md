# Property-Based Tests для Services

## Требования для запуска тестов

Тесты в этой директории используют реальную PostgreSQL базу данных через Prisma Client.

### Предварительные требования:

1. **PostgreSQL должен быть запущен** на `localhost:5432`
2. **База данных должна быть создана и мигрирована**:
   ```cmd
   cmd.exe /c "npx prisma migrate dev"
   ```
3. **Seed данные должны быть загружены** (глобальные упражнения):
   ```cmd
   cmd.exe /c "npx prisma db seed"
   ```

### Запуск тестов:

```cmd
# Запуск всех property-based тестов для services
cmd.exe /c "npm test -- lib/services/__tests__ --run"

# Запуск конкретного теста
cmd.exe /c "npm test -- lib/services/__tests__/workout.service.property.test.ts --run"
```

## Структура тестов

### workout.service.property.test.ts

**Валидирует:**
- **Свойство 4**: Консистентность резолва упражнений (Требования 6.3-6.5)
- **Свойство 22**: Автоматическое создание пользовательских упражнений (Требования 6.4, 16.5)

**Тестовые сценарии:**

1. **Консистентность резолва упражнений:**
   - Повторный резолв одного названия возвращает один ID
   - Резолв не зависит от регистра символов
   - Резолв игнорирует пробелы в начале и конце
   - Разные пользователи могут иметь упражнения с одинаковыми названиями

2. **Автоматическое создание пользовательских упражнений:**
   - Новое упражнение создается с `is_global = false`
   - Глобальные упражнения используются вместо создания новых
   - Глобальные упражнения находятся независимо от регистра
   - Глобальное упражнение имеет приоритет над пользовательским

3. **Граничные случаи:**
   - Пустое название вызывает ошибку
   - Работа с длинными названиями
   - Работа со специальными символами
   - Множественные одновременные резолвы создают только одно упражнение

### user.service.property.test.ts

**Валидирует:**
- **Свойство 10**: Безопасность хеширования паролей (Требование 2.1)
- **Свойство 11**: Уникальность хешей паролей с солью (Требование 2.4)

### verification-tokens.property.test.ts

**Валидирует:**
- **Свойство 23**: Срок действия токенов верификации (Требование 4.5)
- **Свойство 24**: Одноразовость токенов сброса пароля (Требование 4.4)

## Примечания

- Тесты используют `afterEach` для очистки тестовых данных
- Property-based тесты генерируют случайные входные данные с помощью `fast-check`
- Количество итераций (`numRuns`) настроено для баланса между покрытием и скоростью
- Тесты для `user.service` могут выполняться медленно из-за bcrypt (это нормально)

## Troubleshooting

### Ошибка: "Can't reach database server"

**Решение:** Убедитесь, что PostgreSQL запущен:
```cmd
# Проверка статуса PostgreSQL (Windows)
sc query postgresql-x64-15

# Запуск PostgreSQL
net start postgresql-x64-15
```

### Ошибка: "Table does not exist"

**Решение:** Выполните миграции:
```cmd
cmd.exe /c "npx prisma migrate dev"
```

### Ошибка: "Global exercises not found"

**Решение:** Загрузите seed данные:
```cmd
cmd.exe /c "npx prisma db seed"
```

### Тесты выполняются очень медленно

**Причина:** Тесты для `user.service` используют bcrypt с cost factor 12, что требует значительных вычислительных ресурсов.

**Решение:** Это нормальное поведение. Для ускорения можно:
- Уменьшить `numRuns` в тестах
- Запускать тесты выборочно
- Использовать более мощное железо

## Интеграция с CI/CD

Для CI/CD pipeline рекомендуется:

1. Использовать Docker контейнер с PostgreSQL
2. Выполнять миграции и seed перед тестами
3. Использовать отдельную тестовую БД
4. Очищать БД после каждого тестового прогона

Пример для GitHub Actions:

```yaml
services:
  postgres:
    image: postgres:15
    env:
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: workout_tracker_test
    ports:
      - 5432:5432

steps:
  - name: Run migrations
    run: npx prisma migrate deploy
    
  - name: Seed database
    run: npx prisma db seed
    
  - name: Run tests
    run: npm test -- lib/services/__tests__ --run
```
