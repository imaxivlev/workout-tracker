# Документ дизайна

## Обзор

Данный дизайн описывает три независимых улучшения UI для приложения отслеживания кроссфит-тренировок:
1. Улучшенное уведомление при попытке удаления последнего упражнения
2. Обновленные плейсхолдеры для поля результата WOD
3. Новый пресет календаря "За все время"

Все изменения локализованы в существующих файлах и не требуют изменения архитектуры приложения.

## Архитектура

Приложение использует vanilla JavaScript с прямым манипулированием DOM. Изменения будут внесены в:
- `public/workout-tracker/mvp-script-v3.js` - основная логика
- `public/workout-tracker/mvp-index.html` - HTML разметка
- `public/workout-tracker/mvp-styles.css` - стили (при необходимости)

## Correctness Properties

*Property (свойство) - это характеристика или поведение, которое должно выполняться во всех валидных выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Properties служат мостом между человекочитаемыми спецификациями и машинопроверяемыми гарантиями корректности.*

### Correctness Properties

**Property 1: Форматирование ввода времени**
*Для любого* ввода цифр в поле времени, результат должен быть отформатирован как MM:SS, где MM - минуты (00-99), SS - секунды (00-59)
**Validates: Requirements 2.3, 2.4**

**Property 2: Переключение типа результата сохраняет корректное состояние**
*Для любого* типа результата (Time/Reps), переключение на другой тип и обратно должно восстановить корректный placeholder и форматирование
**Validates: Requirements 2.5, 2.6**

**Property 3: Вычисление даты первой тренировки**
*Для любого* набора тренировок в localStorage, функция getFirstWorkoutDate() должна вернуть дату самой ранней тренировки, или сегодняшнюю дату если тренировок нет
**Validates: Requirements 3.3, 3.5**

## Обработка ошибок

### Уведомление об удалении упражнения
- Если tooltip уже существует, переиспользовать его вместо создания нового
- Если не удается добавить слушатели событий, уведомление все равно должно показаться
- Очистка таймера при повторном вызове функции

### Плейсхолдеры результата
- Если элемент input не найден, функция должна завершиться без ошибок
- Если значение select некорректно, использовать значение по умолчанию (reps)

### Пресет "За все время"
- Если localStorage недоступен, использовать сегодняшнюю дату как начальную
- Если данные в localStorage повреждены, пропускать некорректные записи
- Если не удается распарсить дату, пропускать эту тренировку

## Стратегия тестирования

### Двойной подход к тестированию

Для этого проекта будут использоваться:
- **Unit тесты**: Проверка конкретных примеров, граничных случаев и условий ошибок
- **Property тесты**: Проверка универсальных свойств на множестве входных данных

Оба типа тестов дополняют друг друга и необходимы для полного покрытия.

### Unit тесты

Unit тесты должны фокусироваться на:
- Конкретных примерах, демонстрирующих корректное поведение
- Граничных случаях (пустой список тренировок, некорректные данные)
- Условиях ошибок (недоступность localStorage, отсутствие элементов DOM)
- Интеграционных точках между компонентами

**Примеры unit тестов:**
- Проверка текста уведомления "Нельзя удалить единственное упражнение"
- Проверка placeholder "420" для типа "reps"
- Проверка placeholder "04:20" для типа "time"
- Проверка наличия кнопки "За все время" в DOM
- Проверка скрытия tooltip при mouseout
- Проверка скрытия tooltip через 5 секунд

### Property-based тесты

Property тесты должны фокусироваться на:
- Универсальных свойствах, которые выполняются для всех входных данных
- Комплексном покрытии входных данных через рандомизацию

**Конфигурация:**
- Минимум 100 итераций на property тест
- Каждый property тест должен ссылаться на свойство из документа дизайна
- Формат тега: **Feature: workout-tracker-ui-fixes-3, Property {number}: {property_text}**

**Property тесты для реализации:**

1. **Property 1: Форматирование ввода времени**
   - Генерировать случайные строки цифр
   - Применять форматирование
   - Проверять соответствие формату MM:SS

2. **Property 2: Переключение типа результата**
   - Генерировать случайные последовательности переключений типа
   - Проверять корректность placeholder и форматирования после каждого переключения

3. **Property 3: Вычисление даты первой тренировки**
   - Генерировать случайные наборы тренировок с разными датами
   - Проверять, что возвращается минимальная дата
   - Проверять edge case с пустым набором

### Библиотека для property-based тестирования

Для JavaScript рекомендуется использовать **fast-check** - зрелая библиотека для property-based тестирования.

Установка:
```bash
npm install --save-dev fast-check
```

Пример использования:
```javascript
const fc = require('fast-check');

// Feature: workout-tracker-ui-fixes-3, Property 1: Форматирование ввода времени
test('time input formatting property', () => {
  fc.assert(
    fc.property(fc.string({ minLength: 0, maxLength: 4 }), (digits) => {
      const formatted = formatTimeInput(digits.replace(/\D/g, ''));
      return /^\d{0,2}:?\d{0,2}$/.test(formatted);
    }),
    { numRuns: 100 }
  );
});
```

### Баланс между unit и property тестами

- Избегайте написания слишком большого количества unit тестов
- Property-based тесты покрывают множество входных данных
- Unit тесты должны фокусироваться на конкретных примерах и граничных случаях
- Вместе они обеспечивают комплексное покрытие (unit тесты находят конкретные баги, property тесты проверяют общую корректность)
