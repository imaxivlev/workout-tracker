# Документ требований: CrossFit Workout Tracker (MVP)

## Введение

Система для отслеживания тренировок по кроссфиту и тяжелой атлетике. Поддерживает два типа тренировок: Skill (отработка упражнений на максимальный вес) и WOD (Workout of the Day - тренировки типа EMOM, AMRAP, для времени, на количество повторений).

**MVP фокус:** Приложение для отдельных пользователей (без клубной системы). Каждый пользователь создает аккаунт и ведет свою тренировочную историю. В будущем будет добавлена система клубов, лидерборды и геймификация.

## Глоссарий

- **Skill**: Упражнение на отработку техники с постепенным увеличением веса (например: присед 5 подходов 10-10-8-8-6)
- **WOD**: Workout of the Day - тренировка дня (EMOM, AMRAP, для времени, на повторения)
- **EMOM**: Every Minute On the Minute - упражнение каждую минуту
- **AMRAP**: As Many Rounds/Reps As Possible - максимум раундов/повторений за время
- **For Time**: Выполнить все упражнения за минимальное время
- **For Load**: Выполнить за время с максимальным весом
- **Rx**: Регулярная версия WOD (без модификаций)
- **Scaled**: Модифицированная версия WOD (для новичков/менее подготовленных)
- **Пользователь**: Атлет, ведущий тренировочную историю

## Техническое видение

### Платформа
- **Progressive Web App (PWA)**: Веб-сайт, который можно установить на телефон как приложение (иконка на рабочем столе, работа без интерфейса браузера)
- **Адаптивный дизайн**: Приоритет - мобильные устройства

### Стек
- **Frontend**: Next.js + Tailwind CSS (для PWA и современного UI)
- **Backend**: Node.js (в рамках Next.js) + PostgreSQL
- **Развертывание**: Локальная разработка (Docker), с возможностью переноса на VPS (Timeweb)
- **Дизайн**: Агрессивный, энергичный стиль (CrossFit aesthetics), темная тема, крупные шрифты

### MVP-функционал
- Регистрация/авторизация нескольких пользователей
- Создание и запись тренировок (Skill/WOD)
- Календарь выполнения
- История тренировок
- База упражнений с fuzzy search
- Личный профиль

### Планируемые фичи после MVP
- Система клубов и приглашений
- Подписки (клубные/личные)
- Proxy logging
- Лидерборды
- Достижения

## Типы WOD

### По структуре:
- **EMOM (Every Minute On the Minute)**: Выполняешь упражнение в начале каждой минуты, отдыхаешь оставшееся время
- **AMRAP (As Many Rounds/Reps As Possible)**: Максимум раундов или повторений за отведенное время
- **For Time**: Выполнить все упражнения за минимальное время
- **For Load**: Выполнить за время с максимальным весом
- **Ladder**: Повторения увеличиваются или уменьшаются (1-2-3-4-5 или 5-4-3-2-1)
- **Chipper**: Длинная последовательность упражнений с большим количеством повторений
- **Tabata**: 20 сек работы / 10 сек отдыха, 8 раундов

### По инструментам:
- **Калорийные**: Байк (Air Bike), Гребля (Row), Лыжи (SkiErg), Бег (Run)
- **С весом**: Штанга (Barbell), Гантели (Dumbbell), Гиря (Kettlebell)
- **Bodyweight**: Отжимания (Push-ups), Подтягивания (Pull-ups), Бурпи (Burpee), Devil Press, Wall Walks и др.

### Детализация упражнений:
- **Подтягивания**: Chest-to-bar, Strict, Kipping
- **Отжимания**: Hand-release, Standard, Pseudo planche
- **Приседания**: Back Squat, Front Squat, Overhead Squat
- **Тяга**: Conventional, Sumo, Romanian

## Требования MVP

### Требование 1: Регистрация и авторизация

**Пользовательская история:** Как пользователь, я хочу создать аккаунт и войти в систему, чтобы сохранять свои тренировки.

#### Критерии приемки

1. Система ДОЛЖНА позволять зарегистрироваться с email и паролем
2. Система ДОЛЖНА позволять войти в систему с email и паролем
3. Система ДОЛЖНА поддерживать сессию пользователя (авторизация)
4. Система ДОЛЖНА позволять выйти из системы
5. Система ДОЛЖНА хранить данные пользователя изолированно (каждый видит только свои данные)

### Требование 2: Типы тренировок

**Пользовательская история:** Как пользователь, я хочу создавать тренировки разных типов.

#### Критерии приемки

1. Система ДОЛЖНА предоставлять выбор между типами: Skill и WOD
2. При выборе Skill Система ДОЛЖНА запросить:
   - Название упражнения (из справочника или пользовательский ввод)
   - Количество подходов
   - Количество повторений в каждом подходе
   - Максимальный взятый вес
3. При выборе WOD Система ДОЛЖНА запросить:
   - Название WOD (из справочника или пользовательский ввод)
   - Тип WOD (EMOM, AMRAP, For Time, For Load, Ladder, Chipper, Tabata)
   - Время выполнения (если применимо)
   - Количество повторений/раундов (если применимо)
   - Вес (если использовался)
   - Инструмент (байк, гребля, лыжи, штанга, гантели, скакалка и т.д.)
4. Справочник упражнений ДОЛЖЕН включать популярные кроссфит-упражнения с нечетким поиском для предотвращения дублей
5. Система ДОЛЖНА показывать уведомление при создании упражнения, которое уже делал пользователь ранее:
   - "В прошлый раз вы делали это упражнение [дата], результат: [результат]"
   - Кнопка "Перейти к истории упражнений"

### Требование 3: Запись результатов

**Пользовательская история:** Как пользователь, я хочу записывать результаты тренировок.

#### Критерии приемки

1. Система ДОЛЖНА позволять записать результат для каждой тренировки
2. Для Skill Система ДОЛЖНА сохранять:
   - Максимальный вес
   - Количество повторений
   - Дата выполнения
3. Для WOD Система ДОЛЖНА сохранять:
   - Время выполнения или количество повторений/раундов
   - Вес (если использовался)
   - Тип выполнения (Rx/Scaled)
   - Дата выполнения
4. Система ДОЛЖНА позволять редактировать результаты тренировок
5. Система ДОЛЖНА сохранять историю изменений результатов

### Требование 4: Календарь

**Пользовательская история:** Как пользователь, я хочу видеть свои тренировки в календаре, чтобы планировать тренировки.

#### Критерии приемки

1. Система ДОЛЖНА отображать тренировки пользователя на календаре по дням
2. Система ДОЛЖНА показывать статус выполнения (не начато, в процессе, выполнено)
3. Система ДОЛЖНА позволять фильтровать календарь по типу тренировки (Skill/WOD)
4. Клик по дню ДОЛЖЕН открывать детали тренировки

### Требование 5: База упражнений

**Пользовательская история:** Как пользователь, я хочу выбирать из предустановленных упражнений с защитой от дублей.

#### Критерии приемки

1. Система ДОЛЖНА предоставлять предустановленную базу популярных кроссфит-упражнений
2. Система ДОЛЖНА поддерживать нечеткий поиск при добавлении новых упражнений
3. Система ДОЛЖНА предупреждать о возможных дублях при вводе названия
4. Система ДОЛЖНА позволять добавлять пользовательские упражнения

### Требование 6: История тренировок

**Пользовательская история:** Как пользователь, я хочу видеть полную историю всех моих тренировок с удобными фильтрами.

#### Критерии приемки

1. Система ДОЛЖНА отображать список всех тренировок пользователя
2. Система ДОЛЖНА поддерживать фильтрацию по:
   - Типу тренировки (Skill/WOD)
   - Дате (день/неделя/месяц/год)
   - Упражнению
3. Система ДОЛЖНА позволять просматривать детали каждой тренировки
4. Система ДОЛЖНА позволять редактировать результаты тренировок
5. Система ДОЛЖНА сохранять историю изменений результатов

### Требование 7: Личные результаты и статистика

**Пользовательская история:** Как пользователь, я хочу видеть свои лучшие результаты по каждому упражнению, чтобы отслеживать прогресс.

#### Критерии приемки

1. Система ДОЛЖНА сохранять все результаты пользователя по каждому упражнению
2. Система ДОЛЖНА автоматически определять и хранить:
   - Максимальный вес по каждому упражнению
   - Дату достижения максимального веса
   - Лучшее время по каждому WOD
   - Максимальное количество повторений/раундов по каждому WOD
3. Система ДОЛЖНА отображать статистику:
   - Лучший результат
   - Дата лучшего результата
   - Тренд (улучшение/ухудшение за период)
   - Количество выполненных тренировок за период

### Требование 8: Профиль пользователя

**Пользовательская история:** Как пользователь, я хочу настраивать свой профиль.

#### Критерии приемки

1. Система ДОЛЖНА хранить в профиле:
   - Имя пользователя
   - Фотография (аватар)
   - Пол
   - Поле "О себе"
   - Контакты (email, telegram, телефон - опционально)
2. Система ДОЛЖНА предоставлять настройки приватности:
   - Показывать данные всем пользователям
   - Скрыть данные от всех (кроме администраторов)

### Требование 9: PWA функционал

**Пользовательская история:** Как пользователь, я хочу использовать приложение на телефоне как нативное приложение.

#### Критерии приемки

1. Система ДОЛЖНА поддерживать установку на домашний экран (иконка на рабочем столе)
2. Система ДОЛЖНА работать без интерфейса браузера (standalone mode)
3. Система ДОЛЖНА кэшировать статические файлы (HTML, CSS, JS) для быстрой загрузки
4. Система ДОЛЖНА требовать интернета для работы с данными (запись результатов, синхронизация)
5. Система ДОЛЖНА отображать уведомление при отсутствии подключения к интернету при попытке записи результата

**Примечание:** Полноценный Offline-first режим (создание тренировок без сети + авто-синхронизация) вынесен в отдельный фича-реквест после MVP.

### Требование 10: Vibe Coding Design (Эмоциональный UI)

**Пользовательская история:** Как пользователь, я хочу видеть современный, энергичный интерфейс, который мотивирует на тренировку.

#### Критерии приемки

1. Система ДОЛЖНА использовать темную тему по умолчанию
2. Система ДОЛЖНА применять крупную типографику для ключевых элементов (результаты, названия упражнений)
3. Система ДОЛЖНА поддерживать агрессивный/премиум визуальный стиль (CrossFit aesthetics)
4. Система ДОЛЖНА отображать микро-анимации при достижении рекордов (салют, вибрация на мобильных устройствах)
5. Система ДОЛЖНА использовать динамические цветовые акценты для разных типов тренировок

### Требование 11: Умный ввод данных (Smart Input)

**Пользовательская история:** Как пользователь, я хочу быстро вводить результаты тренировок, не тратя время на навигацию.

#### Критерии приемки

1. Система ДОЛЖНА поддерживать fuzzy search (нечеткий поиск) при вводе упражнений (например: "присд" -> "Приседания")
2. Система ДОЛЖНА автоматически предлагать часто используемые упражнения и WOD на основе истории пользователя
3. Система ДОЛЖНА поддерживать быстрые шаблоны для повторяющихся тренировок (например: "Фран" появляется первым при вводе "фр")
4. Система ДОЛЖНА минимизировать количество кликов для записи результата (максимум 3 клика для стандартной тренировки)
5. Система ДОЛЖНА поддерживать ввод с клавиатуры и голосовой ввод (опционально)

### Требование 12: Гибкость редактирования результатов

**Пользовательская история:** Как пользователь, я хочу легко исправлять ошибки в результатах или менять результаты задним числом.

#### Критерии приемки

1. Система ДОЛЖНА позволять редактировать любой результат после его записи
2. Система ДОЛЖНА сохранять историю изменений результата (кто и когда менял)
3. Система ДОЛЖНА позволять создавать нестандартные тренировки без привязки к шаблонам
4. Система ДОЛЖНА поддерживать массовое редактирование результатов за период

## Дополнительные соображения

### Безопасность
- Аутентификация и авторизация пользователей
- Защита данных пользователей
- Разграничение доступа по ролям (для будущих ролей: admin, owner, visitor)

### Масштабируемость
- Поддержка множества пользователей
- Поддержка множества клубов (в будущем)
- Обработка большого количества тренировок
- Хранение истории тренировок
- Возможность переноса на VPS (Timeweb)

### PWA функционал (MVP-scope)
- Установка на домашний экран (иконка на рабочем столе)
- Работа без интерфейса браузера (standalone mode)
- Кэширование статических файлов (HTML, CSS, JS) для быстрой загрузки
- Требование интернета для работы с данными (запись результатов, синхронизация)
- Отображение уведомления при отсутствии подключения к интернету при попытке записи результата

**Примечание:** Полноценный Offline-first режим (создание тренировок без сети + авто-синхронизация) вынесен в отдельный фича-реквест после MVP, так как требует значительных усилий по синхронизации и разрешению конфликтов.
